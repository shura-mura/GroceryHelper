# Issue tracker: GitHub

Issues and specs live in shura-mura/GroceryHelper on GitHub.
Use the GitHub MCP tools for issue operations.

- “Publish to the issue tracker” means create a GitHub issue.
- “Fetch the relevant ticket” means read the issue and its comments.
- Search existing issues before creating one to avoid duplicates.
- Use GitHub sub-issues for parent-child relationships. If unavailable,
  add “Part of #<parent>” to the child and link it in the parent.
- Use native issue dependencies for blockers. If unavailable, record
  “Blocked by: #<number>” in the issue body.
- Apply labels according to docs/agents/triage-labels.md.
- When closing an issue, record the outcome and appropriate state reason.

## Pull requests as a triage surface

PRs as a request surface: no.
