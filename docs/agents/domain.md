# Domain docs

Use a single-context layout:
- GLOSSARY.md at the repository root defines domain vocabulary.
- docs/adr/ contains architecture decision records.

Before exploring the codebase, read the glossary and relevant ADRs.
If these files do not exist, proceed silently. Create them through
domain-modeling when terms or decisions are resolved.

Use the glossary’s terms in issues, proposals, and tests. Note genuine
vocabulary gaps for domain-modeling.

Explicitly flag proposals that contradict an existing ADR, identifying
the ADR and explaining why it should be reconsidered.
